Case Study

Findra

Search intelligence that replaces 10 blue links with one clean data card. Type any name — company, university, landmark — and get structured contact details, location, socials, and more in under 3 seconds.

Role Full-Stack Developer
Timeline 3 Months
Stack React · Node.js · MongoDB · SerpAPI · Claude AI
Status ? Live

The Challenge

Traditional search engines return a flood of links — you type "Harvard University" and get 10 blue links, then spend minutes clicking through pages to find a phone number, email, or address. Freelancers, journalists, and salespeople do this hundreds of times a day.

I wanted to build something different: a search tool that doesn't just find information but actually understands, structures, and presents it as one clean, professional data card — like having a research assistant that works instantly.

How It Works — The Full Pipeline

  • Step 1 — User searches ? React frontend sends the query to the Node.js backend via Axios
  • Step 2 — Cache check ? Backend normalizes the query (lowercase, trimmed) and checks MongoDB. If the same query was searched in the last 7 days, it returns the cached result instantly — zero API cost
  • Step 3 — SerpAPI scrape ? If no cache exists, the backend calls SerpAPI which legally scrapes Google and returns raw knowledge graph, local results, and organic data as JSON
  • Step 4 — Claude AI structures ? The messy raw data is sent to Claude with a strict system prompt. Claude extracts and returns clean, predictable JSON: name, address, phone, email, website, coordinates, timezone, social handles, description, nearby places, and a confidence score (0.0–1.0)
  • Step 5 — Save and return ? The structured result is cached in MongoDB (7-day TTL), saved to user's search history, and displayed as a beautiful data card in under 3 seconds

The Architecture — Layer by Layer

  • Frontend (React.js) — Landing page with animated hero and search bar, results page with structured data cards, user dashboard with search history and stats. All API calls via Axios
  • Backend (Node.js + Express) — Receives search requests, manages the cache-first pipeline, calls SerpAPI and Claude AI, handles JWT authentication and rate limiting
  • Database (MongoDB Atlas) — Three collections: Users (auth data, plan), Searches (history per user with timestamps), and Cache (query results with 7-day expiry — the key to making Findra free to operate)
  • SerpAPI — Legal Google scraper that returns structured JSON. Free plan gives 100 searches/month — combined with caching, this is more than enough
  • Claude AI — The brain that turns messy, inconsistent Google data into clean, predictable JSON regardless of input quality. Also generates entity descriptions and confidence scores

The UI — Dark Premium SaaS

  • Near-black background (#0a0a0f) with animated particle effects in the hero
  • Glassmorphism cards — semi-transparent with blurred borders
  • Indigo-to-cyan gradient accents on buttons, badges, and the logo
  • Framer Motion page transitions between all routes
  • Typewriter effect on the hero headline cycling through example queries
  • Scroll-triggered reveal animations on About and Features pages

Security & Production Hardening

  • Password hashing — bcrypt with 12 salt rounds, never stored as plain text
  • JWT authentication — Tokens expire in 7 days, checked on every protected route (dashboard, history, saved)
  • API key protection — SerpAPI, Claude, and MongoDB credentials stored in .env, never pushed to GitHub
  • Rate limiting — 20 searches/hour for guests, 100/hour for logged-in users
  • Input sanitization — Every query is cleaned before touching the database, preventing injection attacks

The Smart Caching System

The caching layer is what makes Findra financially viable. Every unique search result is stored in MongoDB with a 7-day TTL. When someone searches "Harvard University" and another user searches the same thing 3 days later, the second search is instant and costs zero API credits. This means the 100 free SerpAPI searches/month cover hundreds of actual user searches — because most queries are repeats.

The cache key is the normalized query string (lowercased, trimmed, whitespace-collapsed), so "Harvard University", "harvard university", and " HARVARD UNIVERSITY " all hit the same cache entry.

What Makes Findra Special

  • Full-stack depth — React frontend, Node.js backend, MongoDB database all working together in production
  • Third-party API orchestration — SerpAPI for data, Claude AI for intelligence, JWT for auth — all integrated seamlessly
  • Smart architecture — The caching system demonstrates cost optimization thinking, not just making things work
  • Real problem solving — Solves a genuine pain point that freelancers, journalists, and salespeople actually have
  • Production thinking — Rate limiting, security, error handling, loading states, mobile responsiveness

Results

  • Sub-3-second search results for any entity worldwide
  • Zero-cost repeat searches thanks to 7-day intelligent caching
  • Clean structured data cards with contact info, location, socials, and AI descriptions
  • Production-grade security with JWT, bcrypt, rate limiting, and input sanitization
  • Dark premium SaaS UI with glassmorphism and smooth animations
