Case Study

SharePulse

A Send Anywhere-style file sharing app that transfers files peer-to-peer using WebRTC � no files ever touch the server. Just a 6-digit key and a direct connection.

Role Full-Stack Developer
Timeline 2 Months
Stack React � Node.js � Socket.io � WebRTC � MongoDB
Status ? Live

The Challenge

Most file sharing services upload your files to a remote server � introducing privacy concerns, size limits, and slow transfers. I wanted to build something different: a tool that sends files directly from one browser to another, with zero server-side storage.

The goal was to create a seamless, Send Anywhere-style experience where a sender picks a file, gets a 6-digit code, and the receiver enters that code to start a direct peer-to-peer transfer � no accounts, no uploads, no waiting.

The Approach

  • Built a React + Tailwind CSS frontend with Vite for instant HMR and a clean, modern UI
  • Created a Node.js + Express backend that handles only signaling � generating OTP codes and coordinating WebRTC handshakes via Socket.io
  • Implemented WebRTC RTCDataChannel for direct browser-to-browser file transfer � the server never sees or stores the file data
  • Used MongoDB for temporary metadata storage � file name, size, and MIME type are stored briefly; the OTP expires after 10 minutes
  • Built chunked file transfer over the data channel to handle files up to 100MB reliably
  • Implemented live progress indicators on both sender and receiver sides

How It Works

  • Sender Flow � Selects a file ? backend generates a 6-digit OTP (metadata only, file stays in browser) ? shares OTP or QR code with receiver
  • Receiver Flow � Enters OTP ? verifies against backend ? connects via WebRTC signaling ? receives file chunks directly from sender's browser
  • WebRTC Signaling � Socket.io exchanges SDP offers/answers and ICE candidates, matched by OTP room. Uses Google STUN servers for NAT traversal
  • Security � OTP is one-time use (invalidated after transfer), expires after 10 minutes, and no files are ever stored on the server

Technical Highlights

The core challenge was making WebRTC file transfer reliable across different network conditions. I implemented chunked data channel transfer � files are split into manageable chunks, sent sequentially with flow control, and reassembled on the receiver side. The progress bar updates in real-time on both ends via the data channel's bufferedamount feedback.

For production hardening, the backend includes configurable rate limiting (per-IP and per-OTP action), strict CORS allow-listing, and environment-based TURN server configuration for restrictive networks and mobile carriers. Socket connections are also burst-limited to prevent abuse.

The signaling-only architecture means the backend is extremely lightweight � it handles zero file I/O, making it cheap to host and easy to scale. MongoDB entries are auto-cleaned on a configurable interval (default 30 seconds).

API Architecture

  • POST /upload � Accepts file metadata (name, size, MIME type), generates and returns a 6-digit OTP
  • POST /verify � Validates OTP, returns file metadata to the receiver
  • Socket.io Events � webrtc_offer, webrtc_answer, webrtc_ice � matched by OTP room for peer connection setup
  • Auto-Cleanup � Expired OTPs and metadata are purged every 30 seconds

Results

  • True peer-to-peer file transfer � zero server-side file storage
  • Transfers up to 100MB files with live progress on both sides
  • One-time OTP codes with 10-minute expiry for security
  • Production-ready with rate limiting, CORS, and TURN server support
  • Lightweight signaling backend that's cheap to host and easy to scale
